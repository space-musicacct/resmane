## 2. 前提

本書は、要件定義書「最新型家計簿！『レスマネ』」で「別途決定」とした採用技術を確定するものである。
インフラの稼働方針（Nginx / MySQL を共通基盤とし、本プロジェクト用に専用コンテナ・専用 OS / DB ユーザーを設ける等）は要件定義書 3 章に従う。

### 2.1 Laravel バージョンに関する方針

開発初期段階ではチームメンバーの授業環境に合わせ Laravel 10 / PHP 8.3 を採用していたが、Laravel 10 のセキュリティサポートが 2025年2月に終了しているため、2026年7月に Laravel 13 / PHP 8.5 へアップグレードを実施した。

## 4. 構成図

```mermaid
flowchart LR
    USER[利用者ブラウザ<br/>PC / スマートフォン]
    AI[外部AI API]

    subgraph SERVER[nx-space.com サーバー / Docker Compose]
        NGINX[Nginx<br/>リバースプロキシ / SSL]
        REACT[React + Tailwind SPA<br/>Vite ビルド成果物<br/>フロント専用コンテナ]
        LARAVEL[Laravel 13 / PHP 8.5<br/>API サーバー<br/>バックエンド専用コンテナ]
        WORKER[Python 3.11 worker<br/>schedule で常駐<br/>専用コンテナ]
        MYSQL[(MySQL 8.4)]
    end

    USER -->|HTTPS| NGINX
    NGINX -->|フロント配信| REACT
    NGINX -->|/api, /sanctum| LARAVEL
    REACT -.->|API 呼び出し| LARAVEL
    LARAVEL --> MYSQL
    WORKER --> MYSQL
    WORKER -->|非同期| AI
```

> **フロントエンド（React）とバックエンド（Laravel API）は分離する。** Nginx がパスで振り分け（フロント配信 / `/api`・`/sanctum` → Laravel）、Laravel と React を同一アプリに混在させない（ルーティングの衝突を避けるため）。Nginx と MySQL は共通基盤、レスマネの Web / App 層は専用コンテナとして構築する（要件定義書 3 章準拠）。

## 5. 各層の方針

### 5.1 フロントエンド

| 項目         | 内容                                                         |
| ------------ | ------------------------------------------------------------ |
| 構成         | React による SPA。Nginx が静的配信し、Laravel の API を呼び出す（バックエンドと分離） |
| 言語         | TypeScript                                                   |
| ライブラリ   | React                                                        |
| スタイリング | Tailwind CSS（ユーティリティファースト）                     |
| ビルド       | Vite                                                         |
| 画面方針     | 原則スマートフォン画面を基準とし、PC は Tailwind のレスポンシブ（メディアクエリ）で調整する |
| AIスレッド   | 家計簿詳細とスレッドの表示切替（S-005）はクライアント側で行う |

### 5.2 バックエンド

| 項目           | 内容                                                       |
| -------------- | ---------------------------------------------------------- |
| 提供形態       | API サーバー（JSON）として提供し、画面描画は行わない（フロントと分離） |
| 言語           | PHP 8.5                                                    |
| フレームワーク | Laravel 13                                                 |
| 認証           | ログインID + パスワードによるセッションベース認証          |
| AI生成処理     | 外部AI APIの呼び出しは Python の常駐 worker（5.5）が非同期で担う。Laravel 本体は同期的に AI を呼ばない |
| APIキー管理    | 利用する外部サービスのキーはサーバー側で一元管理する。メール送信は nx-space.com の既存メールサーバーを利用する |

### 5.3 データベース

| 項目         | 内容                                           |
| ------------ | ---------------------------------------------- |
| RDBMS        | MySQL 8.4（共通基盤）                          |
| アクセス     | Laravel（Eloquent ORM）と Python worker から参照する |
| ユーザー分離 | レスマネ専用 DB ユーザーを用い、最小権限で運用 |

### 5.4 インフラ / 実行環境

| 項目             | 内容                                                 |
| ---------------- | ---------------------------------------------------- |
| 実行             | Docker Compose 上のレスマネ専用コンテナ              |
| リバースプロキシ | Nginx（共通基盤）                                    |
| SSL              | Let's Encrypt（Certbot で自動取得・自動更新）        |
| アクセス制御     | 開発・検証段階は WireGuard による VPN 経由に限定する |

### 5.5 AI・バックグラウンド処理

| 項目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 言語     | Python 3.11                                                  |
| 実行形態 | schedule ライブラリで常駐する worker（専用コンテナ）         |
| 役割     | AIフィードバック生成など、外部AI APIを呼ぶ非同期処理を担う   |
| 連携     | Laravel 本体とは分離し、生成要求と結果を受け渡す（連携方式は基本設計で定める） |
| 分離理由 | AI生成の遅延・失敗が Web 表示・入力処理に影響しないよう、バックエンド本体から分離する |
