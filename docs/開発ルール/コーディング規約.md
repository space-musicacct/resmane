## 8. ディレクトリ構成

フロントエンド（React）・バックエンド（Laravel API）・AI worker（Python）は分離し、React は Laravel の `resources` 配下には置かない。層ごとにディレクトリを分ける。

| ディレクトリ | 用途                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| `frontend/`  | React + TypeScript + Tailwind（Vite）の独立した SPA                         |
| `backend/`   | Laravel 10（API サーバー）。`app/Http/Kernel.php` を持つ Laravel 10 標準構成 |
| `worker/`    | Python 3.11 の AI・バックグラウンド worker                                  |

## 9. Git 運用ルール

### 9.1 ブランチ戦略

```
main ← develop ← feature/{担当者}/{トピック}
```

| ブランチ      | 用途                                       |
| ------------- | ------------------------------------------ |
| `main`        | リリース相当の安定版                       |
| `develop`     | 機能を統合する開発ブランチ                 |
| `feature/*`   | 個別の作業ブランチ                         |

#### ブランチ命名ルール

| 項目             | ルール                                                       |
| ---------------- | ------------------------------------------------------------ |
| 形式             | `feature/{担当者}/{トピック}`（担当者より後の階層構造は任意） |
| トピック         | `feature` の場合は動詞（`add` / `edit` / `fix` / `remove` など）から始める |
| 単語の区切り     | ハイフン `-`、すべて小文字                                   |
| 例               | `feature/yuma/edit-requirements-definition` / `feature/yuma/add/dev-rules` |

### 9.2 運用ルール

| 項目             | ルール                                                       |
| ---------------- | ------------------------------------------------------------ |
| マージ           | すべて Pull Request 経由で行う（admin を含め全員）           |
| 直接 push        | `main` / `develop` への直接 push は禁止                      |
| force push       | 禁止                                                         |
| ブランチ削除     | 保護ブランチの削除は禁止                                     |
| レビュー承認     | 承認必須にはしない（マージ担当者の判断でマージ可）           |

### 9.3 コミットメッセージ

| 項目       | ルール                                                       |
| ---------- | ------------------------------------------------------------ |
| 1 行目     | 変更内容の要約（日本語可）                                   |
| 本文       | 必要に応じて、変更の理由・概要を記述する                     |
| 粒度       | 意味のある単位でコミットする                                 |
