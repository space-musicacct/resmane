## 2. 背景

PR #70 において、TypeScript 7・Vite 8・周辺ツールが一括更新された後、修正コミットで TypeScript の範囲指定変更により意図しない 5.9.3 が解決され、同時に CVE-2026-39365 対応済みの Vite 8 が脆弱な 5.4.21 へ巻き戻される事故が発生した（#73・#76）。

また、2026年3月31日には axios の npm メンテナーアカウント侵害により、悪意あるバージョンが公開されるサプライチェーン攻撃（GHSA-658g-p7jg-wx5g）が発生している。

これらを受け、同種事故を防ぐための運用ルールを定める。

## 3. バージョン指定方針

### 3.1 原則: 完全固定

`package.json` の `dependencies` / `devDependencies` には、`^`・`~`・不等号・ワイルドカードを使用せず、完全一致のバージョンを指定する。

```json
"axios": "1.18.1"
"typescript": "5.8.3"
```

以下の指定は禁止する。

```json
"axios": "^1.18.1"
"typescript": "~5.8.0"
"react": ">=18.0.0"
"vite": "8.x"
```

### 3.2 理由

- `npm install` や lockfile 再生成時に、意図しないバージョンが直接依存として採用されるリスクを抑制する
- PR レビュー時に `package.json` だけで採用バージョンが明確になる
- サプライチェーン攻撃で悪意あるパッチバージョンが公開された場合の影響範囲を限定する

### 3.3 推移的依存について

完全固定が保護するのは `package.json` に記載された直接依存のみである。推移的依存（直接依存が内部で利用するパッケージ）は、各パッケージ内の範囲指定に従って lockfile 再生成時に変動し得る。lockfile（`package-lock.json`）を Git 管理し、`npm ci` でインストールすることで推移的依存も固定される。

## 4. 主要ツール互換性対応表

2026-07-26 時点の採用バージョンと互換性を以下に示す。更新時は本表を参照し、互換性を確認すること。

| ツール                    | 採用バージョン | 互換性の制約                                  |
| ------------------------- | -------------- | --------------------------------------------- |
| Node.js                   | 24.16.0        | Vite 8 は Node 20.19+ または 22.12+            |
| TypeScript                | 5.8.3          | @typescript-eslint 8 系は TS >=4.8.4 <6.1.0    |
| Vite                      | 8.1.5          | @vitejs/plugin-react 5 系は Vite 4〜8 対応     |
| @vitejs/plugin-react      | 5.2.0          | 型定義が TS 5.8+ の構文を使用                  |
| React                     | 18.3.1         | @vitejs/plugin-react 5 系は React 18 対応      |
| ESLint                    | 8.57.1         | @typescript-eslint 8 系は ESLint 8.57+ 対応    |
| @typescript-eslint        | 8.65.0         | TS >=4.8.4 <6.1.0, ESLint ^8.57.0 / ^9 / ^10  |

### 4.1 よくある互換性の落とし穴

- **TypeScript の major/minor 更新**: @typescript-eslint と @vitejs/plugin-react の対応範囲を確認する
- **Vite の major 更新**: @vitejs/plugin-react の peerDependencies を確認する
- **ESLint の major 更新**: @typescript-eslint の peerDependencies を確認する

## 5. 更新手順

### 5.1 パッケージの更新

1. **feature ブランチを切る**

   ```bash
   git switch develop
   git pull
   git switch -c feature/{担当者}/update-{パッケージ名}
   ```

2. **`package.json` のバージョンを書き換える**

   更新先のバージョンを完全固定で指定する。

   ```diff
   - "vite": "8.1.5"
   + "vite": "8.2.0"
   ```

3. **lockfile を再生成する**

   ```bash
   docker compose exec frontend npm install
   ```

4. **検証する**

   ```bash
   docker compose exec frontend npm run build    # tsc + vite build
   docker compose exec frontend npm run lint     # eslint
   ```

5. **lockfile の差分で解決バージョンを確認する**

   ```bash
   git diff web/frontend/package-lock.json
   ```

   意図したパッケージのみが更新されていることを確認する。

6. **コミット・PR を作成する**

### 5.2 セキュリティ更新

セキュリティ更新（CVE 対応）は、機能追加・リファクタリングとは別の PR で行う。機能更新の巻き戻しにセキュリティ修正が巻き込まれる事故を防ぐため。

## 6. PR ルール

### 6.1 major update は PR を分離する

複数パッケージの major update を 1 つの PR にまとめない。パッケージごと、または密結合するグループ（例: Vite + @vitejs/plugin-react）ごとに PR を分ける。

ただし、major update に伴い互換性のために他パッケージも更新が必要な場合（例: Vite 8 に上げるために @vitejs/plugin-react も上げる）は、同一 PR で対応してよい。

### 6.2 PR で確認すべきこと

更新 PR では以下をすべて実行し、結果を PR 本文に記載する。

| 確認項目       | コマンド                                       |
| -------------- | ---------------------------------------------- |
| クリーンインストール | `docker compose exec frontend npm ci`    |
| 型チェック + ビルド  | `docker compose exec frontend npm run build` |
| lint           | `docker compose exec frontend npm run lint`    |
| テスト（導入後）| `docker compose exec frontend npm test`        |

### 6.3 コミットメッセージ

更新の意図（なぜこのバージョンへ上げるのか）をコミットメッセージに記載する。
